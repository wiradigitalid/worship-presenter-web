- (decision) Intent=create. v1 scope = otomasi SATU workflow BIC yang sudah ada (proses manual Bimo), belum multi-church; multi-church configurable = visi jangka panjang.
- (decision) Output format fleksibel: file PPTX ATAU web slideshow; downloadable preferred, online slideshow OK asal bagus; cukup 1 transisi elegan standar.
- (decision) Arsitektur 3-lapis: Telegram->picoclaw (baca data, cari lirik, kirim poster) -> API app -> app generate presentasi. Perubahan mengikuti jalur: sesuaikan skill picoclaw -> API -> app.
- (change) addendum.md dibuat: menampung current-state & target-state workflow, actors/access, change-mgmt 3-lapis, housekeeping (delete per-minggu untuk cleanup).
- (decision) kodesh87 = solo developer (bangun & maintain semua lapisan). 'Tim IT' = tim multimedia gereja = end-user/operator NON-teknis, tidak menyentuh kode. Tujuan produk: permudah workflow tim multimedia.
- (decision) Brief untuk memandu build sendiri (bukan pitch, tanpa perlu lampu hijau). Jalur = coaching path.
- (decision) Motif jujur & campuran: hemat ~1 jam/minggu (~52 jam/thn), naikkan kelas peran tim (dari tukang input -> operator otomasi; dept acara bisa komunikasi langsung via Telegram), + pertumbuhan skill/portofolio solo dev. Bukan pemadam kebakaran.
- (decision) Pain nyata: (1) ketik lirik = penyita waktu terbesar + typo pernah tampil di jemaat; (2) perubahan lagu last-minute hampir mustahil -> kapabilitas REVISI jadi nilai jual besar; (3) sisa konten minggu lalu jarang tapi ada; (4) bus factor: hanya Bimo, sejarah tool churn Yosef(pptx)->Galih(FreeWorship)->Bimo(pptx), operator baru lambat di 1st try.
- (decision) VISI: banyak otomasi agar orang gereja lepas dari kerja mekanis & fokus ke misi utama = menjangkau orang lain.
- (decision) Diferensiasi jujur = MODEL AKSES, bukan 'bisa generate slide'. Alasan tinggalkan FreeWorship: setup awal ribet, desktop app sulit diakses ramai, per-komputer ribet, tetap ~30 mnt/mgg, cuma 1 org paham. Keunggulan app: web zero-install + input via Telegram oleh dept acara (kontribusi bukan lagi keahlian spesialis), no gatekeeper, template khas BIC, revisi cepat. Plus jujur: ownership/kontrol + belajar + fondasi otomasi gereja lain.
- (decision) Users: dept acara (kontributor input via Telegram) & tim multimedia (operator) = kelompok BEDA. Bimo bagian tim multimedia, tetap operasikan Sabat. GEREJA KEKURANGAN OPERATOR. Sabat: 2 petugas terjadwal (1 pegang komputer PPTX, 1 sound); keduanya operasikan proyektor/mic/handycam/livestream. Review Jumat & tayang Sabat oleh tim multimedia terjadwal.
- (decision) Primary user = Bimo + tim multimedia (barrier 'harus belajar bikin PPTX' hilang -> kolam operator melebar). Secondary = dept acara. Beneficiary = jemaat. Solo dev = builder/maintainer (bukan end-user tapi butuh maintainability).
- (decision) OUTPUT terkunci: web app = hub (list per-tanggal, preview, review, share link). Web-only OK ASAL handal; unduhan artefak OFFLINE sangat diinginkan, PPTX = bentuk paling disukai (tayang Sabat harus jalan tanpa internet venue; hotspot sebentar utk download). Hybrid diterima. Pilihan teknis .pptx-vs-bundle-web ditunda ke arsitektur.
- (decision) Lagu WAJIB dari SDA Hymnal + nomor SDAH. Lirik diambil dari database hymnal milik user (lookup nomor->lirik), BUKAN web search bebas -> hilangkan risiko typo & hak cipta. Lagu kontemporer/non-hymnal = OUT of scope v1.
- (assumption) DEPENDENCY: database SDA Hymnal akan disediakan user (belum di tangan saat brief ditulis). Diperlakukan sebagai prasyarat input, bukan yang dibangun app.
- (override) REVERSAL: catatan awal 'app bisa diakses publik' DIBATALKAN. App WAJIB password-based, seluruhnya di belakang login. Alasan: aksi kelola (edit/hapus/regenerate) tak boleh terbuka untuk umum.
- (decision) SLIDES vs WEB: PPTX cetak HANYA yang sudah ada di deck (pengkhotbah, closing prayer, family/youth, lagu, ayat, pengumuman). Peran lain TIDAK jadi slide. Web tampilkan FULL rundown (peran+nama+lagu+timing) sbg RUN-SHEET operator (tak perlu buka WhatsApp saat acara). Full rundown = raw input dari dept acara yang diurai picoclaw.
- (decision) SCOPE v1 dikunci (in/out ditulis di brief). Dependency: DB lirik SDA Hymnal disediakan oleh dev (bukan dibangun app).
- (decision) Success criteria diterima tanpa ubah angka. HEADLINE = #1 (beban rakit runtuh), #2 (kolam operator melebar), #6 (terpakai terus). #6 diisi: >=1 kuartal (~13 minggu berturut).
- (decision) REQUIREMENT presentasi: rig 2 monitor (laptop+projektor). Projektor = slide FULLSCREEN bersih, ditangkap OBS utk live stream. WAJIB presenter view (laptop: slide skrg/berikutnya + run-sheet). PPTX: bawaan. Jalur web HARUS replikasi mode presenter dua-layar, bukan sekadar 1 jendela fullscreen. Masuk Scope-IN + step Present di Solution.
- (decision) Vision & Executive Summary didraft. Vision pakai kalimat user: otomasi agar orang gereja fokus ke misi utama = menjangkau orang lain; app ini = wedge, template BIC jadi fondasi ke multi-church. Semua 8 section brief terisi; penanda 'draft in progress' dihapus.
