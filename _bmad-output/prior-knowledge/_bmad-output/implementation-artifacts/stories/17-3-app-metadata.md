# Story 17.3: The App Says Its Own Name

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As anyone with the hub open,
I want the browser tab and bookmarks to name this application,
so that it is not filed as *Create Next App*.

## Acceptance Criteria

1. **The root `metadata` export no longer carries create-next-app boilerplate.** In `src/app/layout.tsx`, `export const metadata: Metadata` no longer has `title: "Create Next App"` or `description: "Generated by create next app"`. `title` names the real application — **`"Worship Presenter Web"`**, the canonical name already recorded in `DESIGN.md` frontmatter (`name: Worship Presenter Web`) and matching `package.json`'s `name: "worship-presenter-web"`. `description` is a short, accurate one-line description of what the hub does; the canonical product-owned one-liner already exists in `DESIGN.md` frontmatter (`description:`, line 3): *"Operator hub for preparing and projecting a worship service."* — use its leading sentence as the default wording. The exact wording is product-owned per the epic — it may be refined at review — but it must not be the create-next-app default and must not name any real congregation, person, or organization.

2. **The change is scoped to the one export, nothing else.** Only the `metadata` object's `title`/`description` fields change in `src/app/layout.tsx`. `export const dynamic = 'force-dynamic'`, the `getUiLocale()` call, the `<html lang>` / `suppressHydrationWarning` / `className` attributes, the `<body>` structure, and the `ThemeProvider` mounting stay byte-for-byte unchanged. No favicon, icon, manifest, other route, component, or projected surface (`slide-surface`, PPTX, projector, slideshow) is touched — this story is the title/description fix only, not a broader branding pass. `tests/theme-chrome.test.mjs`'s existing AC-1/AC-2 assertions that read `src/app/layout.tsx` for the `ThemeProvider` mount and the `suppressHydrationWarning` html mismatch comment continue to pass unmodified.

3. **A regression test protects the property.** A test asserts that `src/app/layout.tsx`'s `metadata` export contains neither the literal string `"Create Next App"` nor `"Generated by create next app"`, and that `title` resolves to the real product name. Extend the existing `tests/theme-chrome.test.mjs` (it already does `read('src/app/layout.tsx')` for AC-1/AC-2, so this avoids introducing and registering a new test file). If a separate new test file is created instead, it **must** be added to the explicit `scripts.test` file list in `package.json` in the same change set — an unregistered test file never runs, in CI or locally, and nothing detects the omission.

4. **The UX authority document is synchronized.** `DESIGN.md` Open Item 3 (*"`metadata` is still create-next-app boilerplate"*, owner: Story 17.3) is marked closed, recording the shipped `title`/`description` values and the date. No other Open Item, token, or component row in `DESIGN.md` is touched. `EXPERIENCE.md` needs no change — this story adds no route, surface, or IA-table entry, and the epic's own preamble records this as `DESIGN.md`-governed operator-chrome identity, not a PRD/FR item.

5. **Repository verification is clean in the supported environment.** On Node.js 22.x (`>=22.12`), the focused theme test, TypeScript check, public-repository guard, and full registered suite pass. `npm run lint` introduces no new problem relative to the current baseline (31 problems as of 2026-08-01/2026-08-03 measurements — re-confirm the live baseline at implementation time rather than trusting this number, per the project-context rule that a working copy with agent worktrees can wildly inflate the count).
