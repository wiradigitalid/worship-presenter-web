## Successes

- The epic's stated goal is met: one saved layout now drives PPTX, web slideshow, presenter and preview, with no per-`SlideKind` layout branch left in any renderer.
- Story 16.1's contract-first foundation (registry, validator, admin API, optimistic concurrency, image safety) held under load. Stories 16.2–16.5 consumed it without a single contract change.
- Keeping `SlidePlanItem` as a superset — hierarchy in `buildArtifactPlan`, flat list from `flattenArtifactPlan` — let six consumer files and `tests/slide-plan.test.mjs` stay untouched through a total planner rewrite.
- One unit-conversion table (`render-model.ts`) is the only place percentages become inches or CSS. PPTX/web drift is now structurally hard rather than merely discouraged.
- Media deduplication plus DEFLATE cut the generated deck from 38.9 MB to 10.1 MB, protecting the offline Sabbath path that registry backgrounds had quietly endangered.
- Story 16.5 (canvas element authoring) came from operator feedback mid-run and was folded in through the same spec rather than bolted on outside the process.

## Challenges

- **Green gates proved almost nothing about content.** `npm test` (139), `tsc`, `build` and lint all passed while three weekly values were silently dropped — the verse reference always printed `1 Corinthians 1:10`, the Special Song performer vanished, and the service date disappeared from the Welcome slide. Family & Youth additionally printed both prayer texts twice and hid the family photo behind the youth photo. Only adversarial review caught any of it.
- **The canvas editor could not open at all.** An explicit `undefined` `fontStyle` reached Fabric v6's font cache and threw for every shipped text element. Story 16.1 shipped and closed with this defect because no test and no manual pass ever mounted the editor.
- **Saving an untouched template silently corrupted it.** Fabric's `initDimensions()` discards the authored box, so a no-op save rewrote the geometry of every text element. Harmless in 16.1; load-bearing the moment 16.3 made layouts drive output.
- **The seed was treated as trustworthy input.** Placeholders declared but bound to nothing, and the same placeholder bound to two elements, passed the validator because the contract never required the two to agree.
- **The smoke guard had rotted into a tautology** — grepping `slide-plan.ts` for slide ids proves nothing about what the deck says.
- **Two competing decompositions coexisted.** `epics-parallel-delivery-analysis.md` proposed Stories 16.2–16.8 but was never reconciled into `epics.md`, sprint status or the SPEC companions (its own AR19 required that first). It is now marked superseded.

## Key insights

1. **A schema validator is not a content validator.** `registry-contract.md` enforces shape; nothing enforced that a declared placeholder is actually rendered exactly once. That single missing rule caused four of the seven high-severity findings. A conformance test asserting *placeholders declared == placeholders bound* would have caught all of them at seed time.
2. **Data-driven rendering moves the blast radius from code review to data review.** The diff was clean and well-typed; the defects were in a 28-template JSON file nobody reads line by line.
3. **Assert rendered output, not intermediate structures.** The new `tests/pptx-content.test.mjs` — which unzips the deck and reads the actual text runs — is the regression net that all the unit tests together did not provide.
4. **"Done" on a UI story needs the UI to have been opened.** Story 16.1 closed against passing tests and a build; the editor was unopenable.
5. **The BMad gate worked.** Everything went Epic → Story → Spec → implement → adversarial review → triage, and the process is what surfaced the defects rather than the tests.
