# Story 24.1: A String Catalogue, a Switcher, and an Honest `lang`

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an operator who reads Indonesian more comfortably than English,
I want to set the hub's language and have the page say which language it is in,
so that the interface meets me where I am and a screen reader is not lied to.

## What this story is, in one sentence

The **infrastructure** half of FR-25 — a string catalogue that is code rather
than data, one settings key, one admin block on the shipped per-concern pattern,
and `<html lang>` following the setting instead of the hard-coded `"en"` — and
**no sweep**: moving the 100–150 strings is Story 24.2.

**Why it is separate from the sweep, in the epic's own words:** *"the
infrastructure decision is small and worth reviewing on its own, and the sweep is
large and worth reviewing as a sweep."* Every decision this story takes, 24.2
inherits 100–150 times over. That is the whole reason this story exists as a
unit, and it is why the mechanism questions below are ACs rather than notes.

## Acceptance Criteria

1. **The catalogue is code, versioned with the code that renders it — not a table, not a row, not a corpus.** AD-25 anticipated this story **by name**: *"FR-25's UI string catalogue is **not** a reference corpus and does not go into the database at all: it is interface text read at render and versioned with the code that renders it, with no row, no reconcile and no registry entry."* It is named there because Epic 24 lands beside Epics 21 and 22 and ships `<locale>`-keyed files within weeks of them, and *"persisting them would give the same string two homes and hand a redeploy the job of a migration."* So: modules under `src/lib/`, one table per locale. The only thing this story persists is `ui_locale` itself.

2. **Resolution is a pure function in a `.ts` module, and a stored value is untrusted.** Key + locale → string, callable directly by `node:test` — the project's rule is that *logic worth testing lives in a `.ts` module, never inside a `.tsx` component*, and `src/lib/theme-cycle.ts` is the precedent it names. Follow that file's shape, including its coercion idiom: an unrecognised stored `ui_locale` reads as the default (`asThemeChoice`'s counterpart) rather than being trusted. **Two locales ship** — `en` (default) and `id` — because Flow 9's whole point is an operator setting the hub to Indonesian, and a switcher with one option is not the requirement.

   **The UI-locale vocabulary is *not* the data-locale vocabulary, and they must not share a list.** A UI locale exists because a **catalogue shipped with the code**; a data locale exists because a **corpus file was installed**, discovered at runtime by Story 21.2's loader. The sets legitimately differ — an Indonesian song book can be installed with no Indonesian catalogue in the build, and the reverse — so the switcher offers *the locales this build has catalogues for*, never *the locales some corpus declares*. Sharing one constant or deriving one from the other is the exact conflation PRD §4.12 opens by saying it exists to prevent: *"Language enters this product at exactly two independent places, and conflating them is the failure this section exists to prevent."*

3. **An unresolved key is visible as a defect, never blank, and never silently English.** A key with no entry renders a marker that **names the key** and logs server-side; it does **not** fall back to `en`. A silent fallback is precisely the failure FR-25 names — *"a missing translation that fails silently is how half a UI ships in the wrong language without anyone noticing"* — and English-looking text in an Indonesian hub is indistinguishable from an untranslated string nobody has noticed yet.

4. **A key added to one locale and not the other is a red suite, not a defect an operator finds.** The catalogues hold the **same key set**, asserted. This is what makes AC-3's no-fallback rule affordable for Story 24.2: the sweep adds keys in pairs or the suite says so, at the moment the key is added rather than the moment an operator switches language.

5. **`ui_locale` is persisted-shared, admin-written, and exactly one key.** `settings.ts` takes one `const` plus a getter and setter on the two shipped precedents (`RETENTION_KEY:10`, `SLIDE_TRANSITION_KEY:13`) — **append-shaped, and you take one key of the four.** It is **not** `localStorage`: that tier is view-preference-only and is the theme's (AD-24), and a value the whole install shares is persisted-shared by definition. **One consequence recorded rather than solved:** there is no per-account persisted tier — every write path into `settings` is `requireAdminSession` — so this is one language for the whole install, not per operator. The spine records that limitation and where it would be revisited; this story does not close it and must not invent a per-user table to.

6. **The switcher is the shipped per-concern block, it is its own component, and it introduces no new visual vocabulary.** A `card` on `/admin` holding a native `select` and a `button`, on `admin/TransitionSettings.tsx`'s pattern; the Server page reads the setting and passes it in as an `initial*` prop, exactly as `admin/page.tsx:52-54` already does three times. **Its own component — not a shared "language settings" card.** `EXPERIENCE.md:73` fixes this in as many words: the two corpus defaults *"follow the shipped per-concern settings pattern onto `/admin`, `ui_locale` follows the same pattern onto the same page"* — **per-concern means one component each**, and the *"Language block"* of Flow 9 step 2 is reached by adjacency, not by one card three stories co-own. A shared card is a file Stories 21.3 and 22.3 would each have to rewrite, which is the merge the 2026-08-01 cut exists to avoid. **No new design token and no chromatic affordance**; if you find yourself needing either, stop — that is a `DESIGN.md` change and `AGENTS.md` requires it in the same change set. The confirmation follows the rule `DESIGN.md` already sets for `admin/TransitionSettings`: say **what** changed and **where** it lands — and here, that nothing projected changes.

7. **`<html lang>` follows the setting, and it is not frozen at build time.** `layout.tsx:31`'s literal `lang="en"` reads `ui_locale`. The trap is real and specific: the root layout is a Server Component that declares no `dynamic`, and of the nine pages, five declare `force-dynamic` and one more reaches `next/headers`, leaving `src/app/login/page.tsx` with **neither** — so a naive read bakes `lang` into that route at build time and the setting silently does not apply there. **Prove it with `npm run build`'s route table** (`○` static versus `ƒ` dynamic) rather than by reasoning, and whichever way you close it, record the trade in the Completion Notes.

8. **The theme boundary and the root layout's server-ness survive intact.** `suppressHydrationWarning` (`:32`, with its reason at `:27-29`) stays — next-themes writes the theme class onto `<html>` before hydration and removing the suppression turns that expected mismatch back into an error. `ThemeProvider` stays the one client boundary at `:36`. **Do not put `'use client'` on `layout.tsx`** — the project's rule says it converts the whole app and to never do it — and do not move `lang` out of the root layout, because only the root layout may render `<html>`.

9. **No second root-level client provider — and if you conclude one is needed, that is a decision to state and route, not to take.** The rule is fixed: a client boundary *"mounts at the narrowest layout covering its consumers, and never on `layout.tsx` itself"*, and *"to add a provider, enumerate its consumers and mount at the narrowest layout containing all of them — 'simpler at the root' is not that enumeration."* You do not need one: every client component in this app already receives server-read state as an `initial*` prop, which is the same channel a locale travels on. And the question is **already open above you** — the spine's *Deferred* records the second root-level provider as a live question whose first test is Story 17.6's toast channel, on AD-24's *must wrap every route* bar. Landing one here, inside an infrastructure story, would answer a question two other stories are queued behind.

10. **Nothing this story builds reaches a room-facing surface, and the one clause needing a judgement is stated rather than left for review.** Projector, slideshow and PPTX read neither the catalogue nor `ui_locale`, asserted by a test — **necessary because this is a product rule and not a structural impossibility**: a room-facing surface legitimately reads `settings` today (AD-23's `slide_transition` is exactly that), so nothing stops `ui_locale` being read there except this assertion. **The exception is `<html lang>` itself, and it is deliberate.** The root layout wraps the room-facing routes too, so the document language follows the setting there as well. That is the correct reading of two artifacts that pull slightly apart: FR-25 requires the document language to follow `ui_locale` with no route carved out, while the closure Epic 17 states is about what the congregation **sees** — and `lang` paints nothing, renders no string, and changes no pixel. Recorded here as the clause a reviewer should check, rather than found in review.

11. **Only the strings this story introduces are routed through the catalogue.** Its own block's labels, its confirmation, its `select` options. Nothing else moves — the sweep is 24.2's, the `slide-plan.ts` labels are 24.2's, `metadata` is 17.3's. `THEME_LABEL` (`theme-cycle.ts:31-35`) is three English strings in a module you are reading as a precedent; **it is 24.2's, not yours.**

12. **Between this story and 24.2 the hub is bilingual in one block, and that is the expected state.** Switching to `id` translates what this story routed through the catalogue and nothing else, because every other string is still an inline literal rather than a missing key — AC-3's defect marker does not fire for a string that never became a key. Say so in the Completion Notes so a reviewer does not read it as a bug, and do not "fix" it by starting the sweep.

13. **Everything above is tested, and the suite is registered in the same change set.** `node:test` with `--experimental-strip-types` under `tests/*.test.mjs`, listed in `package.json` `scripts.test` **in the same change set** — an unregistered test file never runs, locally or in CI, and nothing detects the omission. Cover: the resolver; a junk stored value coercing to the default; the missing-key defect (visible, names the key, not blank, **not** English); key-set parity (AC-4); the API's validate-before-write and its body gate (AC-5); and the room-facing closure (AC-10). **Prove the closure guard reacts** — add a catalogue import to a projected file, watch the suite go red, revert, `git status --short` clean.

14. **The suite is green, the build is checked, and the switch is exercised end to end.** `npm test` green with the new suite registered; `npx tsc --noEmit` clean; `npx eslint src tests` no worse than the clean-checkout baseline and **zero** problems in any file you touched; `npm run build` green (AC-7 needs its route table anyway). Manual pass, recorded: set the hub to Indonesian in Settings, reload, confirm `<html lang="id">` in the **served markup** rather than in the source, confirm the projector and slideshow are unchanged, switch back.

### Why the provider question is the sharpest thing in this story

Reaching two dozen client components with a locale looks like a provider, and the pull is strong precisely because the root is *simpler*. Three things say no, and they compound:

- The project rule names the shortcut and forbids it: *"'simpler at the root' is not that enumeration."*
- The shipped idiom already solves it — `initialTransition`, `initialDays`, `initialAccounts` are all server-read state arriving as props, and a locale is the same kind of value.
- The bar is **already open above you.** AD-24's *Deferred* records the second root-level client provider as a live question, first tested by Story 17.6's toast channel; a locale provider at the root would answer it as a side effect of an infrastructure story, and it would wrap the room-facing routes AC-10 exists to keep closed.

Passing a locale as a prop also makes AC-10 nearly structural instead of merely asserted: a surface that is never handed the value cannot read it.

### What must be preserved

- **`ThemeProvider` is the one root client boundary and the reason it is allowed is enumerated** — theming's consumers are every route. Passing `children` through it does not make them client components; they arrive already server-rendered. Whatever you build must not change that sentence.
- **The theme's tier is not yours to borrow.** The theme lives in `localStorage` because it is a view preference that need not travel; `ui_locale` is app-wide and admin-owned, so it is persisted-shared. Two adjacent settings, two different homes, and AD-24's *who must agree on it* is the question that picks each.
- **The all-or-nothing property of `PUT /api/admin/settings`.** A body mixing a good field with a rejected one must leave **both** stored settings untouched — the comment at `:50-52` is the contract, and a third field is exactly when someone writes the first one before validating the third.
- **`getSlideTransition`'s posture on a junk stored value:** coerce to the default and `console.error`, never throw. Deck generation reads that setting on every download and *"a junk row must never be the reason a service has no slides."* The same reasoning applies to `ui_locale` — a hand-edited settings row must not be able to blank the hub.

### No authorization surface is added, and the absence is a finding rather than a silence

AD-5 makes `src/proxy.ts`'s `config.matcher` regex **the** authorization boundary, and a new control is precisely when somebody reaches for it. Verified in this worktree: `/admin` and `/api/admin/**` are already inside the matcher and already admin-gated, and `PUT /api/admin/settings` already re-checks the role against SQLite via `requireAdminSession` (`route.ts:17`,`:29`) rather than trusting the cookie. You add a field to an existing gated route and a block to an existing gated page, so **no matcher change and therefore no `tests/proxy-matcher.test.mjs` change** — stated because adding an exclusion here would be the AD-5 violation, and adding nothing is correct.
